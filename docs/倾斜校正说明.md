# 倾斜校正（Deskew）说明

> 自动纠偏 + 手动微调：手机拍摄的书法图片经常倾斜，本功能让切割网格恢复轴对齐。

## 两层校正

| 层级 | 触发时机 | 实现 |
|------|---------|------|
| **自动纠偏** | 上传图片时 | 后端投影轮廓法自动检测 ±10° 范围内的倾斜 |
| **手动旋转** | 切割布局页面手动操作 | UI 三个按钮：↺ 1° / 1° ↻ / 重置 |

## 一、为什么需要倾斜校正？

手机拍摄书法图片常见的 5–10° 倾斜，会让：

- OCR 检测的文本框（AABB 轴对齐框）多包空白
- 红色线（列边界）算出的"中位间隙"位置歪掉
- 蓝色线（行边界）按 y 轴算间隙时，每行的字被切错位
- 字符被斜着切开或漏切

倾斜的图片 → 切割网格错位 → 字符被切坏。纠偏把图片恢复到轴对齐，让红/蓝/绿三色线按预期工作。

## 二、自动纠偏

### 算法：投影轮廓法（Projection Profile）

对 [-10°, +10°] 范围每个角度旋转缩略图，计算水平投影（每行白像素求和）的**方差**。方差最大时文字最水平（峰值最尖锐）。

### 边界场景

| 场景 | 处理 |
|------|------|
| 二值图白像素比例 < 0.5% 或 > 99.5% | 跳过纠偏（空白或全黑图）|
| 检测角度 < 0.1° | 跳过旋转（避免无谓损失）|
| 倾斜 > 10° | 截断到 ±10°（剩余倾斜需手动旋转）|
| 单张检测耗时 | ~80ms（在 1024px 缩略图上）|

### 端到端测试（6/6 通过）

| 测试 | 期望 | 实际 |
|------|------|------|
| 水平图 | 0° | 0° ✓ |
| 旋转 +7° | -7° | -7° ✓ |
| 旋转 -3° | +3° | +3° ✓ |
| 旋转 +10°（边界） | -10° | -10° ✓ |
| 全白图 | 0° | 0° ✓ |
| 全黑图 | 0° | 0° ✓ |

> 算法返回值的符号约定：返回的是「需要旋转的反向角度」。旋转 +7° 的图检测出 -7°，按 -7° 反向旋转即可恢复水平。

## 三、手动旋转

### UI（切割布局页面）

在「手动调整」面板：

```
┌─────────────────────────────┐
│  ↺ 1°   1° ↻     重置      │
│                             │
│  [ 识别当前旋转 ]            │
│                             │
│  当前累计旋转：0°            │
└─────────────────────────────┘
```

- **↺ 1°**（左按钮）：逆时针旋转，**仅旋转**图片，不重新检测
- **1° ↻**（右按钮）：顺时针旋转，**仅旋转**图片，不重新检测
- **重置**：恢复到自动纠偏后的状态，**仅旋转**图片，不重新检测
- **识别当前旋转**（橙色高亮）：手动触发文本框检测 + 切割线分析

### 工作流程

```
点击 ↺/↻ 多次调整角度 ──→ 图片跟随旋转 ──→ 点击「识别」
                                              ↓
                                    重新检测文本框 + 切割线
                                              ↓
                                    红/蓝/绿三色线更新
```

**为什么分离？** 每次旋转都重跑识别浪费——OpenCV 轮廓检测虽然不慢，但累积多次点击后开销可观。分离后用户可连续点击调整角度，最后点一次「识别」。

**「识别」按钮的视觉提示**：旋转/重置后按钮变为**橙色脉冲**（`.btn-detect-stale` class），提示需要重新识别。识别完成后回到默认青色。

### 后端文件存储（`static/uploads/`）

| 文件 | 内容 |
|------|------|
| `{hash}.png` | **当前显示图**——二值化 + 缩放，被手动旋转反复覆盖 |
| `{hash}_base.png` | **彩色基准图**——纠偏后 + 所有手动旋转累积 |
| `{hash}_original.png` | **原图副本**——纠偏后基准，用于「重置」 |

> 关键：手动旋转始终基于**彩色** `_base.png`，最后才二值化。避免直接对二值图旋转产生灰边。

### API 端点

| 端点 | 作用 | 返回 |
|------|------|------|
| `POST /api/upload` | 上传时自动纠偏，保存三个副本 | 含 boxes + cut_lines |
| `POST /api/rotate` | 增量旋转，body: `{hash, angle}` | 仅 image_url + 尺寸 |
| `POST /api/reset_image` | 重置到纠偏后基准，body: `{hash}` | 仅 image_url + 尺寸 |
| `POST /api/detect` | 对当前图片重新检测，body: `{hash}` | boxes + cut_lines |

rotate/reset 仅旋转图片（快），detect 才重新跑文本框检测 + 切割线分析（稍慢）。

## 四、旋转方向约定

**OpenCV 的 `getRotationMatrix2D(center, angle, scale)` 中，正值 = 逆时针旋转。**

| 按钮 | 图标 | 实际行为 | 后端 angle 参数 |
|------|------|---------|---------------|
| 左 | ↺ 1° | 逆时针 | +1° |
| 右 | 1° ↻ | 顺时针 | -1° |

> 调试小记：之前左右按钮的点击事件接反了——图标方向一直是对的，但传给后端的 angle 符号错位。现已修正。

## 五、限制与后续

- **自动纠偏局限**：仅搜索 ±10°；印章混排、垂直排版可能误判
- **手动步长固定 1°**：需要更大角度时多次点击
- **若效果不佳**，可考虑：
  - 加 Hough 备选算法
  - 加按列检测置信度
  - 引入手动角度输入框（任意角度）
