# 调整字符画笔工具

> /adjust 页面弹窗中的画笔功能：选色、画线、画完可保存到字符图。

## 1. UI 位置

调整字符 modal 右侧栏，在「切割范围」下方：

```
[ 颜色 ] [#000000]            ← 颜色选择器
[ 黑 ] [ 白 ] [ 红 ] [ 绿 ] [ 蓝 ] [ 黄 ]    ← 预设色
[ 大小 ] [——————o——]  5        ← 滑块
         [ 5 ]                ← 数字输入
[ ✏ 画笔模式：关/开 ]         ← 切换按钮
```

切到「开」状态时：
- 鼠标变红色圆圈（半径 = 大小/2）
- 中心一个小红点（精确定位）
- 拖动即在图上画

## 2. 架构

两层 canvas 分离：

| 层 | 内容 | 是否烘焙到图 |
|----|------|--------------|
| **主 canvas** | 原图 + overlay（合并后）+ 圆圈 | overlay 部分被烘焙 |
| **overlay canvas** | 真实笔触 | ✓ 烘焙时合入图 |

### 为什么这样设计？

- 圆圈是「视觉指示器」，不属于最终图
- 笔触是「用户创作内容」，需要保存
- 分离后：圆圈自由刷新，笔触持久保留
- confirm/保存时只合并 overlay，**圆圈不会进图**

## 3. 圆圈半径计算

```javascript
const imgSize = parseInt(brushSizeInput.value, 10);  // 图片坐标（像素）
const radius = (imgSize * canvasState.scale) / 2;     // → canvas 坐标
```

- `brushSizeInput.value` = 用户设置（图片坐标）
- 乘以 `canvasState.scale` = 图片 → canvas 的缩放比例
- 除以 2 = 半径

例：设置 10px，scale=0.4 → 画在 canvas 上 2px 半径 = 4px 直径 → 对应图片 10px 直径 ✓

## 4. 加载优化

### Flask 缓存头

```python
@app.route('/output/<path:filename>')
def serve_output(filename):
    response = send_from_directory(OUTPUT_FOLDER, filename)
    response.headers['Cache-Control'] = 'public, max-age=31536000, immutable'
    return response
```

文件名带 hash+序号，唯一 → 强缓存一年。

### URL cache key 升级

旧版：`?t=${Date.now()}` → 每次击穿缓存，**无意义**的网速开销

新版：`?v=${char.cache_version || 0}` → 文件未变时复用浏览器缓存

```javascript
img.src = `${char.image_url}?v=${char.cache_version || 0}`;
```

应用调整/画笔后 `cache_version++` → 强制重新请求最新图。

### 加载指示器

`loadCharToCanvas` 中显示「加载中…」覆盖层，`onload` 隐藏：

```html
<div class="canvas-loading">加载中…</div>
```

避免用户误以为图片卡住。

## 5. 修复的 bug 历史

### bug 1：圆圈残留在图片中

**现象**：用户用画笔后，鼠标移出 canvas 再点「确定」，圆圈被烘焙到图里。

**根因**：`drawBrushCursor` 画在主 canvas，鼠标离开后无 mousemove → 不重绘 → 圆圈残留在主 canvas → confirm 烘焙时一并保存。

**修复 1（首发）**：`onmouseleave` 触发 `redrawCanvas()`，清除主 canvas 上的圆圈。

### bug 2：圆圈拖尾/破环图片

**现象**：移动鼠标时画笔破坏图片（红圈轨道 + 圆圈本身）。

**根因**：`drawBrushCursor` 移到 overlay 层后：
- 每次 `redrawCanvas` 都把整个 overlay（含上次的圆圈）画到主 canvas
- 然后 `drawBrushCursor` 又在新位置画新圆圈
- 旧圆圈在 overlay 持续累积 → 拖尾
- confirm 烘焙时这些圆圈全进图

**修复**：`drawBrushCursor` 改回主 canvas，但不画在 overlay 上。这样：
- overlay 只含真实笔触（持久）
- 圆圈只在主 canvas 临时显示
- `redrawCanvas` 重绘主 canvas 时圆圈自动清除
- `onmouseleave` 不需要额外处理（圆圈本来就不在 overlay）
- confirm 烘焙 overlay → 只笔触进图，圆圈不进

### bug 3：Ctrl 在 canvas 内松开，圆圈残留

**现象**：使用 Ctrl 画笔快捷键时，鼠标在 canvas 内按下 Ctrl → 拖动 → 松开 Ctrl，圆圈残留在 canvas 上。

**根因**：
- 按住 Ctrl → brushMode = true → mousemove 触发 `redrawCanvas() + drawBrushCursor(x, y)`
- 松开 Ctrl → brushMode = false（keyup 处理器设的）
- 但 `keyup` 不触发 `mousemove` → 主 canvas 上画过的圆圈没被清掉

修复前和修复 1 看似重叠，但区别是：
- 修复 1 是 `mouseleave`（鼠标离开 canvas 触发）
- 本 bug 是 `keyup`（鼠标仍在 canvas 内就松 Ctrl）

**修复**：在 keyup 处理器里也调用 `redrawCanvas()` 强制清掉残留圆圈。

```javascript
document.addEventListener('keyup', (e) => {
    if (!adjustModalOpen) return;
    if (e.key === 'Control' && canvasState.brushMode) {
        canvasState.brushMode = false;
        canvasState.isPainting = false;
        updateBrushToggleButton();
        redrawCanvas();   // ← 关键：keyup 不会触发 mousemove，要主动清
    }
});
```

边界：
- 按住 Ctrl → 鼠标移出 canvas → 松 Ctrl：`canvas.onmouseleave` 早 redraw ✓
- 按住 Ctrl → 鼠标在 canvas 内 → 松 Ctrl：keyup 调用 redrawCanvas ✓
- 两种场景都干净

### bug 4：confirm 时把 4 条剪切框线烤进图

**现象**：用 Ctrl 画完笔触后点「确定」保存，保存的图片四周有红色矩形框线（裁剪参考线）。

**根因**：
- Ctrl 释放 → `brushMode = false`
- `redrawCanvas` 看到 `!brushMode` → 调用 `drawAdjustBox` 画 4 条红框
- 用户点「确定」→ `bakeOverlayToImage()` 把笔触合并到主 canvas
- `canvas.toDataURL()` 抓取主 canvas → **把框线也编码进 image_data**
- 服务器保存这张图，红线就永久留下了

**修复**：在 `toDataURL` 前临时把 `brushMode` 设为 `true`，让 `redrawCanvas` 跳过框线；捕获完恢复。

```javascript
bakeOverlayToImage();
const canvas = document.getElementById('adjustCanvas');
const prevBrushMode = canvasState.brushMode;
canvasState.brushMode = true;            // ← 抑制框线
redrawCanvas();                          // 重绘无框线版
canvasState.char.image_data = canvas.toDataURL('image/png');
canvasState.brushMode = prevBrushMode;   // 恢复
redrawCanvas();                          // 重绘带回框线
```

副作用：用户视觉上看到的 canvas 仍带框线（最后一次 redraw 恢复了），但保存的图是干净的。

### bug 5：画笔内容保存丢失（被原图覆盖）

**现象**：用 Ctrl 画完笔触后点「确定」，保存到服务器的图是**原图**（无笔触）。修改的图片被原图覆盖。

**根因**：bug 4 修复时引入的新问题。`redrawCanvas` 会**清空整个主 canvas**（`ctx.clearRect`）再重绘 image + overlay。`bakeOverlayToImage` 后，overlay 已被 `clearRect` 清空，**再次 `redrawCanvas` 等于把刚烤的笔触擦掉**。

```
bakeOverlayToImage()       ← 笔触 → 主 canvas
canvasState.brushMode = true
redrawCanvas()              ← 清空主 canvas、重画 image + 空 overlay → 笔触被擦
canvas.toDataURL()          ← 抓到的是空 image
canvasState.brushMode = false
redrawCanvas()              ← 还原
```

服务器收到无笔触的 image_data，cv2.imwrite 写入 → 等于原图。

**修复**：去掉 bake 和 toDataURL 之间的 `redrawCanvas`。`brushMode=true` 仅作「抑制框线」的标志，不触发重绘。

```javascript
bakeOverlayToImage();                  // 笔触 → 主 canvas
const canvas = document.getElementById('adjustCanvas');
const prevBrushMode = canvasState.brushMode;
canvasState.brushMode = true;           // 标志位（不重绘）
canvasState.char.image_data = canvas.toDataURL('image/png');  // 抓到带笔触
canvasState.brushMode = prevBrushMode;
redrawCanvas();                         // 恢复显示（仅一次）
```

时序对比：

|步骤 | 之前（有 bug 4 修复时）| 现在 |
|------|----------------|------|
| 1 | bake 笔触 | bake 笔触 |
| 2 | `brushMode = true` | `brushMode = true` |
| 3 | `redrawCanvas` 擦掉笔触 ❌ | **跳过** |
| 4 | `toDataURL` → 空 | `toDataURL` → 含笔触 ✓ |
| 5 | 恢复 brushMode | 恢复 brushMode |
| 6 | redraw 还原 | redraw 还原 |

## 6. 调整字符 modal 的其他相关功能

| 功能 | 触发 | 文件 |
|------|------|------|
| 切割范围调整（拖动橙线） | 拖动画布边缘 4 条线 | `loadCharToCanvas` + `handleMouseDown/Move/Up` |

| 画完保存 | 「应用」/「确定」/「保存并下一个」 | confirm 烘焙 overlay → 图 |
