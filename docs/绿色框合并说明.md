# 绿色框合并说明（按距离自动合并）

> 一个字被检测成几块（笔画断开、印章与正文分家、偏旁被切开）时，
> 按「两个绿框的边缘间距 ≤ 阈值」把碎片自动并成一个框。

入口：「绿色框设置」模态框底部的「按距离合并绿框」区块（阈值滑块 + 间距直方图 + 按钮）。

---

## 两种合并方式

页面1 有两条合并绿框的路径，**分组方式不同，但「合并动作」完全共用**：

| 方式 | 触发 | 适合 |
|------|------|------|
| **框选合并**（原有） | `Ctrl+Alt` + 左键拖一个矩形；或点标题栏「合并绿色框」后再拖 | 手工挑几个框并 |
| **按距离合并**（本文） | 「绿色框设置」里设好阈值 → 点「按距离合并绿框」 | 批量处理零散碎片 |

「合并动作」指：新框 = 组内所有框的最小包围盒，再刷派生字段、夹到图片范围内，最后删旧框加新框。
两处都走这一段（[static/js/layout.js](../static/js/layout.js) 的 `performMerge()` 与 `mergeGreenBoxesByDistance()`）。

---

## 一、间距怎么算：边缘间距

取两个矩形**最接近处**的直线距离：先分别求 x / y 方向的间隙，重叠方向的间隙记 0，再取欧氏距离。

```
dx = max(0, max(a.x_min - b.x_max, b.x_min - a.x_max))
dy = max(0, max(a.y_min - b.y_max, b.y_min - a.y_max))
gap = √(dx² + dy²)
```

```
① 上下相邻             ② 左右相邻              ③ 斜对角
  ┌────┐                ┌────┐┌────┐             ┌────┐
  │ A  │                │ A  ││ B  │             │ A  │
  └────┘                └────┘└────┘             └────┘
    ↕  gap = dy            ↔  gap = dx              ⟍  gap = √(dx²+dy²)
  ┌────┐                                           ┌────┐
  │ B  │                                           │ B  │
  └────┘                                           └────┘

④ 交叠（部分重叠）                ⑤ 包含（B 整个在 A 里）
  ┌────────┐                        ┌──────────────┐
  │  A     │                        │  A           │
  │     ┌──┼─────┐                  │    ┌─────┐   │
  └─────┼──┘     │                  │    │  B  │   │
        │   B    │                  │    └─────┘   │
        └────────┘                  └──────────────┘

  ④⑤ 的 gap 都是 0 —— 任何阈值下都会合并
```

**为什么这么定义**

- 间隙方向重叠时该方向记 0：两个框在同一列上下相邻时，只有 y 方向有间隙，x 方向「间隙」是负数（重叠），必须夹到 0，否则会算出一个无意义的负距离。
- 斜对角用欧氏距离而非「x 间隙 + y 间隙」：这是矩形间距的标准定义（两点最接近时的直线距离），斜着挨近的两个碎片本来就更「近」。
- **交叠 / 包含 → 0**：0 ≤ 任何阈值，所以这类框对**任何阈值下都会合并**。这是有意为之——大量重复检测（同一个字被检成一大一小两个框）就靠它清掉。副作用见第七节。

## 二、怎么分组：连通分量（并查集）

不是「两两配对后各并一次」，而是把**间距 ≤ 阈值的框对连成一张图，取连通分量**：

```
阈值 = 5px 时：

  A ──5px── B ──5px── C         → A、B、C 同属一个连通分量，并成 1 个框
  A ──5px── B    C ──3px── D    → A、B 并成 1 个；C、D 另并成 1 个（共 2 组）
  A ──8px── B                   → 8 > 5，两组独立，不并
```

否则 A-B 近、B-C 也近时，用户得反复点按钮才能把链式相邻的碎片收干净。
实现用并查集（路径压缩），一次遍历所有满足阈值的框对即可完成分组。

**规模上限的保护**：建表时只保留间距 ≤ `MERGE_DIST_MAX`（50px）的框对——而滑块量程也是 0–50px，
所以「阈值能取到的任何框对」必然都在表里（这是量程与建表上限必须一致的原因，改一个就要改另一个）。

## 三、合并动作

对每个「至少 2 个框」的组：

1. 求组内所有框的最小包围盒（`x_min` 取最小、`x_max` 取最大，y 同理）
2. `syncBoxDerived(mergedBox)` 刷派生字段（`width` / `height` / `center_*` / `area`）
3. `clampBoxToImage(mergedBox)` 夹到图片范围内（内部会再同步一次派生字段）
4. 从绿框集合里按**对象引用**剔除组内旧框，把新框加进去
5. `markBoxModified()` → 标记「检测结果已过期」（标题栏「开始识别」会变色提示）、重绘画布、刷新 UI

合并前压一次撤销栈（`pushHistory()`），所以整批合并可以一键撤回（见第八节）。

---

## 四、与过滤解耦，但同步主集

模态框里有两套操作，**互不触发**：

| 操作 | 按钮 | 作用 |
|------|------|------|
| 过滤 | 底栏「应用」 | `state.boxes = masterBoxes.filter(谓词)` |
| 合并 | 「按距离合并绿框」 | 只改绿框集合，不读不写不触发任何过滤条件 |

但合并**必须同步主集 `masterBoxes`**，否则合并白做：

```
合并 → state.boxes = 2 个（合并态）、masterBoxes = 4 个（未合并）
点「应用」 → state.boxes = masterBoxes.filter(...) → 又变回 4 个（合并被丢弃）
```

所以合并时把旧框从 `state.boxes` 和 `masterBoxes` **两边**都按引用剔除，再把合并框补进两边
（两个数组里的绿框本来就是同一批对象引用，主集靠 `slice()` / 展开复制而来），并 `persistMasterBoxes()` 落盘。

**过滤预览统计的口径**：模态框里的「总数 / 保留 / 过滤掉」读的是主集，所以合并后这些数字会一起变——
这是对的：合并是「绿框集合真的变了」，统计理应反映。

## 五、直方图：纵轴为什么是「框对数量」

横轴 = 边缘间距 0–50px（线性，每格 2px）；纵轴 = **落在该区间的框对数量**，不是绿框数量。

因为合并不是逐框判断，而是**成对判断**：调阈值时用户真正关心的是「这一拉会吃掉多少对」。
比如 1379 个框里有 404 对落在 0–2px，把阈值拉到 2px 就是这 404 对全部参与合并。

阈值左侧的柱子高亮（会被本次合并吃掉），右侧灰显；橙色竖线 = 当前阈值，可直接拖动选值
（拖拽做了 CSS 缩放换算——画布 `width:100%` 时显示宽度未必等于 500px，只用鼠标偏移会算歪）。

## 六、缓存：为什么要，以及怎么判过期

建表是 O(n²)：1379 个绿框约 95 万次比较，实测约 99ms。
直方图重绘、滑块拖动都发生在这个量级上，所以必须缓存。

**过期判定用「数组实例 + 坐标签名」双校验，两者缺一都会出错**：

| 校验 | 覆盖的场景 | 缺了会怎样 |
|------|-----------|-----------|
| 数组实例 `===` | 撤销 / 过滤会把 `state.boxes` 换成**坐标完全相同的深拷贝** | 缓存里的 `{a,b}` 还指向旧对象 → 合并时按引用一个都查不到 → **静默地一对都不合并** |
| 坐标签名（数量 + 坐标和） | 拖动 / 缩放是**原地改坐标**，数组实例不变 | 间距已经变了却仍用旧缓存 |

> 踩过的坑：最早只比签名。真实数据上表现为「阈值调大反而一个都不并」——
> 阈值 0 并掉 337 个，阈值 2/5/10/20/50 全是一个都不并。根因就是撤销/过滤换成了深拷贝。

代码里另有一道兜底：合并时若某个框对的对象已不在当前集合，直接跳过（不崩，但也不误并）。

## 七、真实数据参考（1379 个绿框的实测）

调阈值前先看这张表，并留意 toast 里的「绿框 N → M 个」：

| 阈值 | 合并后框数 | 减少 |
|------|-----------|------|
| 0px | 1042 | 337 |
| 2px | 953 | 426 |
| **5px（默认）** | **859** | **520** |
| 10px | 791 | 588 |
| 20px | 733 | 646 |
| **50px** | **114** | **1265** |

**连锁传播比直觉猛得多**：阈值 50px 会把 1379 个框并成 114 个——因为 A-B 近、B-C 近就并成一组，
沿着整列能一路连下去。所以：

- 默认 5px 已经并掉 520 个，第一次用建议先小后大、配合直方图看
- 并过头了直接 `Ctrl+Z` 撤回（整批合并只压一次撤销栈，一次即可还原）

---

## 八、与撤销 / 重做的关系

- 合并前 `pushHistory()`：整批合并只压**一次**栈，一次撤回就回到合并前
- 快照包含 `state.boxes` **和** `masterBoxes`：撤回才能连主集一起回滚。
  主集不回滚的话，「撤回」之后再点「应用」会把合并态又拉回来（撤销被抵消）
- 快捷键：`Ctrl+Z` 撤销、`Ctrl+Y` / `Ctrl+Shift+Z` 重做。
  焦点在输入框时不拦截——输入框里的 `Ctrl+Z` 交给浏览器撤掉刚打的字
