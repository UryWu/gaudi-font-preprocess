# 数据存储说明

> 用户操作触发的数据落盘位置：原图、切割线配置、切割结果字符图。

## 总览

```
┌─────────────────────────────────────────────────────────────┐
│ 静态目录（图片）                                              │
│   static/uploads/{hash}.png            当前显示图（二值化）   │
│   static/uploads/{hash}_base.png       彩色基准（纠偏+旋转）  │
│   static/uploads/{hash}_original.png   原图副本（重置用）     │
├─────────────────────────────────────────────────────────────┤
│ 配置目录（切割线）                                            │
│   data/sessions/{hash}.json            切割线+绿框配置      │
├─────────────────────────────────────────────────────────────┤
│ 输出目录（切割结果）                                          │
│   output/{hash}/char_NNNN.png          切割后的字符图       │
│   output/{hash}/scaled/scaled_NNNN.png 缩放校正后的字符图    │
└─────────────────────────────────────────────────────────────┘
```

## 路径常量

定义在 [config.py](../config.py)：

| 常量 | 值 | 作用 |
|------|-----|------|
| `BASE_DIR` | 项目根目录（脚本所在目录或 exe 所在目录）| 所有路径的基准 |
| `UPLOAD_FOLDER` | `<BASE_DIR>/static/uploads` | 原图+基准图+原图副本 |
| `DATA_FOLDER` | `<BASE_DIR>/data/sessions` | 切割线 JSON 配置 |
| `OUTPUT_FOLDER` | `<BASE_DIR>/output` | 切割后字符图 |

## 数据生命周期

```
[上传图片]
  POST /api/upload
  ├─ 保存原图:        static/uploads/original_{filename}
  ├─ 计算哈希:        file_hash = md5(原图)
  ├─ 自动纠偏（可选）: deskew(img)
  ├─ 存原图副本:      static/uploads/{hash}_original.png     ← 始终不变
  ├─ 存彩色基准:      static/uploads/{hash}_base.png         ← 跟随手动旋转更新
  ├─ 二值化 + 缩放:   static/uploads/{hash}.png              ← 当前显示（被旋转覆盖）
  ├─ 检测文本框:      boxes (in-memory)
  └─ 分析切割线:      vertical_lines, horizontal_lines, strip_horizontal_lines

[手动旋转（每次点 ↺/↻）]
  POST /api/rotate
  ├─ 旋转 _base.png: 累积旋转结果（彩色）
  ├─ 二值化+缩放:     覆盖 {hash}.png
  └─ 不更新 boxes / cut_lines（"识别"才更新）

[点「开始识别」]
  POST /api/detect
  ├─ 读取 {hash}.png（当前已旋转的二值化图）
  ├─ 检测 boxes
  ├─ 分析 cut_lines
  └─ 返回前端

[点「存储切割线」]   ← 立即落盘
  POST /api/save_cuts
  └─ 写入: data/sessions/{hash}.json
     {hash, vertical_lines, horizontal_lines, strip_horizontal_lines, boxes}

[点「应用切割」]      ← 立即生成字符图
  POST /api/apply_cuts
  ├─ 读取 {hash}.png
  ├─ 按当前 boxes/切线切割
  ├─ 写入: output/{hash}/char_NNNN.png  (每个字符一张图)
  └─ 返回每片的元数据 (index, x, y, width, height, is_empty, source)

[点「重置」]
  POST /api/reset_image
  ├─ 用 {hash}_original.png 覆盖 {hash}_base.png
  ├─ 重新二值化+缩放 → {hash}.png
  └─ 重置累计旋转角度

[跳转到「缩放校正」]
  POST /api/process_scale
  └─ 读取 output/{hash}/char_NNNN.png
     缩放+居中处理后写入: output/{hash}/scaled/scaled_NNNN.png

[点「导出 FontLab」」
  POST /api/export_annotated
  ├─ 读取 output/{hash}/ 下的字符图
  ├─ 颜色反转（白底黑字）
  └─ 按 Unicode 命名（uniXXXX.bmp / uXXXXX.bmp）写入新目录
```

## 文件命名约定

| 文件名 | 含义 |
|--------|------|
| `original_{filename}` | 用户上传的原图（PyInstaller 打包时）|
| `{hash}.png` | 当前显示图（md5 哈希取自原图内容）|
| `{hash}_base.png` | 彩色基准图，跟随手动旋转累积 |
| `{hash}_original.png` | 原图副本，仅在「重置」时使用 |
| `data/sessions/{hash}.json` | 切割线配置 |
| `output/{hash}/char_{idx:04d}.png` | 切割字符图，idx 从 0000 开始 |
| `output/{hash}/scaled/scaled_{idx:04d}.png` | 缩放后的字符图 |
| `output/{hash}/exported/{timestamp}/` | 导出的 FontLab 命名目录 |

## 关键约定

- **`{hash}` 是基于上传原图内容的 MD5**。同一张图多次上传得到相同 hash，第二次上传会复用之前的会话数据。
- **同名文件覆盖**：重复点「应用切割」会用新结果覆盖 `char_NNNN.png`，不会创建新文件。
- **原图永远不变**：`{hash}_original.png` 只在「重置」时**读取**，从不被写入覆盖，保证可还原。

## 验证示例

```
1. 上传图片
2. 从页面「图片信息」读出哈希前 12 位，例如 c508565e8b8c
3. 文件管理器打开 <项目根>/，应该看到：
   static/uploads/c508565e8b8c.png         (显示图)
   static/uploads/c508565e8b8c_base.png    (基准)
   static/uploads/c508565e8b8c_original.png (副本)
4. 点「存储切割线」
   data/sessions/c508565e8b8c.json         (新建)
5. 点「应用切割」
   output/c508565e8b8c/char_0000.png      (新建)
   output/c508565e8b8c/char_0001.png
   ...
```
